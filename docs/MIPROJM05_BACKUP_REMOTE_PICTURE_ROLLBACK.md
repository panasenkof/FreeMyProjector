# MiProjM05 — пульт, изображение, резервное копирование и откат (P-04/P-05)

**Статус 24.10.2026:** обязательный проект процедуры, **не выполненный backup и не проверенный rollback**. Xiaomi MiProjM05/eva, Android TV 9 API 28, build `PQ3B.190705.003.4185`. Пока `ModeJob.PROJECTOR_HOME_SWITCH_AUDITED = false`: не меняем HOME, OEM-пакеты, настройки, сопряжение или калибровку.

Связано с [P-04](P04_HOME_SAFETY_AUDIT.md), [P-04A](PROJECTOR_FUNCTIONS.md), [обнаруженными Intent](MIPROJM05_ACTIVITY_DISCOVERY.md) и [CleanYourTV](CLEANYOURTV_MIPROJM05_RESEARCH.md).

## 1. Обязательные функции до любого изменения HOME

### Пульт: подключение, сопряжение, повторное подключение
- Установить реальный способ соединения комплектного пульта (Bluetooth/ИК), где в OEM-меню показано сопряжение, как проводится повторное сопряжение, без выдуманных комбинаций кнопок.
- Проверить Home, Back, D-pad/OK, Power, сон/пробуждение, кнопки громкости **включая долгое удержание**, кнопку настроек/шестерёнки, микрофон/голос (если предусмотрено) и возврат из HDMI/приложения.
- После сна и холодной загрузки проверить автоматическое подключение; отдельно проверить путь повторного сопряжения и работу пульта при сбое нашего лаунчера. Не зависеть от FreeMyProjector для Bluetooth pairing.
- Проверить альтернативный канал управления (совместимая USB-клавиатура/ИК/управление с ПК — только после фактической проверки). Без независимого способа восстановления управления **HOME не переключать**.
- Сохранить OEM Bluetooth/input/remote/voice компоненты, в том числе `com.droidlogic.ble`; не применять key-remapping, Accessibility и неизвестные службы перехвата. В CleanYourTV для сборки `.2102` кнопка шестерёнки → KEYCODE_ALL_APPS (284), но их helper нарушал авто-повтор громкости. У нас пока гипотеза для read-only проверки.

### Изображение: отдельный экран «Изображение» из фото владельца
- На фото видны **«Режим изображения»** и пункт, связанный с **яркостью камеры**; не путать её с яркостью источника света. Подтвердить точный смысл по меню и определить, какие ещё параметры действительно есть (цвет/контраст/резкость/температура, ориентация/режим проекции и прочее, если доступны).
- Сфотографировать исходные выбранные режимы, текущие числа и переключатели; не менять их ради диагностики.
- Обеспечить в будущей оболочке доступ к **заводскому экрану регулировки изображения**, а не подменять его не проверенным `settings put` или своим HAL-контроллером.
- Сохранить фокусировку, трапецию, автоматическую коррекцию и **отдельную** автоматическую калибровку. `START_AUTO_KEYSTONE` не доказывает автоматическую калибровку.

## 2. Резервная копия: различать снимок состояния и прошивку

### A. Обязательный доступный без root снимок ДО первого изменения
Создать на ПК пользователя отдельный **read-only** инструмент P-04 для локального архива с датой и SHA-256, который сохраняет:
1. Точные model/device/build/SDK; фактически resolved HOME и список HOME claimants, исходный `com.google.android.tvlauncher/.MainActivity`.
2. Список установленных и **исходно отключённых** пакетов, включая enabled-state всех затрагиваемых и защищаемых Fengmi, Formovie, Droidlogic, TV Launcher, Camera2, Bluetooth/input/сеть. Повторный snapshot после изменения **никогда не перезаписывает** оригинал.
3. Только доступные без записи сведения о заводских настройках пульта/сети/HDMI, заставки и разрешений, результат диагностики Activity, версию нашего APK.
4. Фото заводских меню изображения, фокусировки/трапеции, сопряжения, зафиксированные человеком значения. Запись в системные настройки не выполнять.
5. Локальный читаемый отчёт о полноте, checksum, ошибках и отсутствующих полях; при неполноте — **STOP**.

Хранить локально вне GitHub, не публиковать полный dumpsys, серийный номер/IP/MAC/Wi-Fi/токены. По необходимости зашифровать хранилище.

**Это НЕ полный образ прошивки или backup /data, vendor, HAL и калибровок**. На Android 9 без root их нельзя гарантированно выгрузить; `adb pull` одного `FengmiImaging.apk` не равен прошивке. Поэтому не обещать автоматическое восстановление любого повреждения.

### B. Полное восстановление / аварийная прошивка (отдельное исследование)
- Проверить наличие официальных recovery/OTA именно для `MiProjM05/eva` нужной аппаратной ревизии/региона и версий, механизм возврата, риски калибровки. **Ничего не прошивать.**
- Документировать восстановление при одновременной потере HOME, ADB, Wi-Fi и пульта. Заводской сброс может удалить данные и не гарантирует восстановить OEM калибровку; это не эквивалент проверенному откату.
- Без реального аварийного способа восстановления **не выполнять системные действия, способные оставить аппарат без HOME**.

## 3. Протокол допуска — последовательные независимые ворота

**Этап 0. Read-only baseline:** полный снимок A + контролируемое сохранение, идентификация экспорта/разрешений OEM Activity, текущие настройки изображения, пульта, pairing, входа HDMI, доступность резервного управления; никаких `am start` и `settings put`.

**Этап 1. Пилот обычного APK:** только по отдельному согласованию владельца установить подписанный FreeMyProjector и открыть **как обычное приложение**, НЕ делая его HOME и НЕ отключая Google/OEM. Проверить кнопку Back/Home, пульт, возврат штатных экранов и заводской функционал. Падение — вернуться штатной кнопкой HOME; никаких системных изменений, приложение можно удалить отдельно.

**Этап 2. Доказанный сценарий rollback:** создать и протестировать на моках Android 9: оригинальный snapshot неизменяем; восстанавливать только изменённое, включая заводской HOME и *предыдущее* enabled/disabled состояние, не `pm enable` всех приложений. Не считать `FallbackHome` или factory-test Activity рабочим HOME; `cmd role` на API 28 считать недоступным до проверки. Проверить идемпотентность, ошибки на каждом шаге, фактический HOME после возврата и отказ при изменившейся прошивке.

**Этап 3. Опциональный HOME-пилот (отдельное разрешение):** лишь после успешных этапов 0–2 и независимого пути спасения — временный выбор нашего HOME **без отключения заводского лаунчера и OEM-пакетов**. Контроль `resolve-activity` (не доверять одному сообщению Success), пульта, pairing, картинки, оптики, HDMI, Wi-Fi, сна/холодного старта. При любой регрессии — возврат исходного HOME, проверка действительного результата.

**Этап 4. После перезагрузки/OTA:** повторная приёмка, сравнение snapshot. Изменился build/компоненты — fail-closed, снова P-04; никаких автоматических отключений/«исправлений» системных пакетов.

### Матрица аварийного отката (пока проект, не проверенные команды)
| Состояние | Планируемый путь восстановления |
|---|---|
| Наш UI работает | Кнопка «Вернуть заводский экран», с проверкой реально активного HOME |
| Наш UI сломан, ADB доступен | Локальный заранее проверенный на API28 runbook восстановления HOME и **только** записанных изменённых состояний |
| ADB недоступен, пульт работает | Заранее проверенный OEM путь в системные настройки/выбор HOME (если он существует) |
| И ADB, и пульт недоступны | STOP. Пока независимый путь восстановления не проверен, запрещать рискованные изменения HOME |

## 4. Чек-лист приёмки перед разблокировкой

- [ ] Снимок до изменений действительно **снят на ПК, проверен, защищён и не перезаписывается**; отсутствующее отмечено.
- [ ] Реальное заводское сопряжение и **повторное подключение** пульта проверены, включая холодный старт.
- [ ] Есть проверенный путь управления независимо от работы нашего лаунчера.
- [ ] Проверены кнопка настроек/голос/долгое удержание громкости/Back/Home/D-pad/сон.
- [ ] На фото записаны исходный режим «Изображение» и значения (включая уточнение «яркости камеры»), после теста не изменены.
- [ ] Фокус, коррекция, калибровка и HDMI не сломаны; штатные экраны доступны.
- [ ] Доступ к imaging aliases подтверждён из обычного APK без HOME switch; отказ не обходится привилегиями.
- [ ] Процедура возврата исходных Home + enabled/disabled проверена на моках, затем отдельно в допустимом режиме на устройстве.
- [ ] Владелец дал отдельное согласие на системный пилот, подготовлен проверенный emergency access.
- [ ] После настоящего возврата все функции и состояние сохранены после перезагрузки.

**До исполнения этих критериев `PROJECTOR_HOME_SWITCH_AUDITED=false`.**
