# P-04G — ADB-восстановление, доступ к заводскому сопряжению пульта и осторожная диагностика подключения

**Стадия: архитектурное решение, 25.10.2026. Без изменения состояния проектора.** Модель MiProjM05/eva, Android TV 9 (API 28), сборка `PQ3B.190705.003.4185`. Заводской HOME — `com.google.android.tvlauncher/.MainActivity`, активный пользователь — `0`. P-04B и P-04E совпали с SHA-проверенным снимком 114 пакетов, P-04D прошёл пять офлайн-сценариев. Фактический HOME rollback **ещё не проводился**; `ModeJob.PROJECTOR_HOME_SWITCH_AUDITED=false`.

## 1. Может ли ADB вернуть заводской HOME?

**Да, потенциально, пока ADB доступен.** AOSP Android 9 предоставляет `cmd package set-home-activity [--user USER_ID] TARGET-COMPONENT`. Документированная реализация API 28: https://android.googlesource.com/platform/prebuilts/fullsdk/sources/android-28/+/refs/heads/androidx-activity-release/com/android/server/pm/PackageManagerShellCommand.java . Конкретные возможности и поведение на OEM .4185 **не проверены командой записи**; сообщение `Success` не доказывает, что фактический HOME изменился.

**Будущий отдельный PC-only recovery (НЕ ВНЕДРЕНО и НЕ РАЗРЕШЕНО К ЗАПУСКУ):**
1. Проверить исходный снимок (SHA256), модель/build, единственный authorized ADB, user 0, наличие и enabled исходного лаунчера + Fengmi/Formovie/Droidlogic/Bluetooth.
2. Сначала показать сухой diff и получить отдельное подтверждение для *конкретного* изменения. Журнал исходных/новых значений сохранять атомарно **до** записи, с hash и ограниченным перечнем затронутых полей.
3. Только затем, при отдельно разрешённом аппаратном пилоте, применять точечный Android-9-способ выбора исходного HOME, не используя `cmd role` как Android 9 fallback. По умолчанию не выполнять `pm disable`, `pm enable`, массовых восстановлений пакетов, root, сбросов, калибровки.
4. Повторно читать реально разрешённый HOME для user 0 и проверять работу пульта, настроек, сна и cold boot; при любой неоднозначности — STOP без цепочки дополнительных команд.
5. Наличие ADB по сети до эксперимента не гарантирует доступ после потери сети, adb-авторизации, boot или службы ввода. Нужен второй проверенный аварийный путь (G1, G4 из P-04F) перед HOME-switch.

**Примечание:** уже созданные `Compare-ProjectorBaseline.ps1` и `Test-ProjectorRollbackLocally.ps1` ничего не восстанавливают — только проверяют и моделируют.

## 2. Заводское меню пульта: не переносим службу, а сохраняем и открываем штатную Activity

- Не трогать оригинальные `com.android.tv.settings`, `com.fengmi.fmsettings`, `com.fengmi.platform`, `com.formovie.gsettings`, `com.droidlogic.ble`, Bluetooth/system input/voice и другую OEM-цепочку; не выполнять debloat или перепривязку аппаратных кнопок.
- **В нынешнем `SettingsActivity` есть только общий пункт "TV Settings"**, открывающий `Settings.ACTION_SETTINGS`. Выделенного, уже проверенного перехода в сопряжение пульта **нет**.
- Добавить в дизайн P-06 отдельный пункт **«Пульт и Bluetooth»**. В первую очередь открывать штатную, проверенную на `.4185` Activity пульта/аксессуаров (после пассивного resolver/manifest preflight), не собственный экран подключения. Запасной вариант — стандартный `Settings.ACTION_BLUETOOTH_SETTINGS`, только если он действительно разрешается на устройстве и пригоден для управления с пульта. Android API предупреждает, что подходящей Activity может вообще не быть: https://developer.android.com/reference/android/provider/Settings#ACTION_BLUETOOTH_SETTINGS .
- Заранее сделать кнопку «Все настройки проектора», которая остаётся доступной независимо от успешности нового ярлыка; не удалять доступ к OEM Settings из launcher.
- Кнопка не должна сама сбрасывать bond, отключать Bluetooth или инициировать pairing; запуск экранов требует отдельного теста обычного APK без замены HOME.
- По FAQ Xiaomi для Mi Smart Compact Projector процесс сопряжения заводского пульта предусмотрен (с удержанием Home+Menu вблизи устройства, около 20 см). Сведения модели/региона и фактическую комбинацию для данного пульта проверить при необходимости, **не начинать переподключение сейчас**: https://www.mi.com/ru/support/faq/details/KA-04467/ .

## 3. Поведение на старте: не запускать Bluetooth pairing без достоверного признака

Предлагаемый приоритет:
- **P0: ручной доступ** к «Пульт и Bluetooth» и к общим заводским настройкам, при этом сохранение OEM Bluetooth и автоподключения пульта.
- **P1: необязательная подсказка** «Пульт не обнаружен — открыть подключение?» только на *нашем видимом экране*, после завершения загрузки/периода ожидания (например, конфигурируемые 30–60 с) и когда **достоверно** установлено отсутствие именно известного Bluetooth-пульта. Если статус неизвестен или подключение лишь кратковременно прерывалось — подсказку не показывать. По умолчанию включить только ручной пункт, автоматическую подсказку — после тестов и с opt-in/возможностью выключить.
- **P2: режим восстановления ввода** — показывать невмешивающуюся в OEM сервис инструкцию и короткий путь в заводской экран, когда пользователь *явно* вызывает помощь/запрашивает повторное сопряжение. Не открывать pairing UI поверх холодной загрузки, HDMI, медиаплеера или других Activity без согласия.
- Не делать автоматическое `removeBond`, `createBond`, сброс сопряжений, Bluetooth-enable/disable, pairing в фоне; не пытаться восстанавливать системные пакеты автоматически.

**Техническое ограничение Android 9:** `InputDevice.getDeviceIds()` / `InputManager` умеют перечислять присутствующие устройства ввода, но не доказывают Bluetooth bonding/соединение конкретного заводского пульта; отсутствие нажатий также не доказывает разрыв связи. На Android 9 HID Host-профиль `BluetoothHidHost` представлен скрытым API AOSP, без гарантий для обычного APK. Нельзя путать `BluetoothHidDevice` — роль периферийного устройства — с HID Host-профилем проектора. Источники: https://developer.android.com/reference/android/view/InputDevice ; https://android.googlesource.com/platform/prebuilts/fullsdk/sources/android-28/+/4d01eeaffaa720e4458a118baa137a11614f00f7/android/bluetooth/BluetoothHidHost.java . Если достоверно различить сопряжённый/подключённый пульт по публичному API нельзя, оставляем **только ручную кнопку**, без ложных предупреждений.

Отдельно учесть, что запуск нашего лаунчера при boot ещё не означает, что Bluetooth stack завершил восстановление связи; не вводить новый foreground/background сервис, autostart или Accessibility для этого раннего сценария.

## 4. Беспроводная USB-клавиатура с донглом — не эквивалент Bluetooth-пульта

Владелец уточнил: USB-клавиатура **беспроводная**, используется USB-приёмник. На проекторе клавиши не работают, USB HID не подтверждён. Такой радиодонгл обычно предъявляет себя Android как USB HID и не требует Bluetooth-пары с проектором, но совместимость конкретных устройств/ресивера неизвестна. До покупок проверить эту пару (приёмник+клавиатура) на ПК; можно read-only проверить USB/input enumeration на MiProjM05 и сопоставить результат **без передачи serial/MAC**. Не объявлять USB-порт сломанным. Отдельный возможный временный запасной путь — Google TV phone virtual remote в той же сети, если поддерживается данным устройством и успешно сопряжён, но **это тоже зависит от сети и сервисов**. https://support.google.com/androidtv/answer/6122465

**Новое решение владельца 25.10.2026:** USB-клавиатура исключена из планов аварийного управления; без её проверки и покупки. Предпочтение отдано PC-ADB recovery с ограничениями и одноразовому [P-04I watchdog](P04I_ONE_TIME_WATCHDOG.md). По фирменному меню pairing — [P-04H](P04H_REMOTE_PAIRING_DISCOVERY.md), отчёт владельца ещё нужен до утверждения точной Activity.

## 5. Следующие PR и условия приёмки

1. **P-04G.1 — read-only**: выяснить конкретную OEM Activity сопряжения в `com.android.tv.settings`/`com.fengmi.fmsettings`/`com.formovie.gsettings`, подтвердить resolver, exported и permissions; проверить USB keyboard receiver enumeration и доступность Android 9 package HOME help через разрешённые только-читающие запросы. Не запускать Activity и не менять настройки.
2. **P-06.1 — UI**: после верификации и согласия внедрить безопасные пункты «Пульт и Bluetooth», «Все настройки», «Фокусировка», «Трапеция», «Возврат к оригинальному HOME» (последнее отключено до recovery). Функции открытия заводских Activity — отдельные контролируемые аппаратные испытания.
3. **P-06.2 — статус пульта**: отдельный исследовательский прототип, включать подсказку только после точного распознавания пульта и только по opt-in; если нельзя надёжно определить, останется ручной запуск.
4. **P-04G.2 — recovery**: контракт и fake-ADB тесты read-only + будущего write-механизма с fail-closed; физический HOME-пилот допускается **только после G1/G2/G4 и отдельного явного согласования**.

**Главный принцип:** установить приложение как обычный APK с сохранённым Google HOME можно протестировать отдельно раньше, чем назначать FreeMyProjector системным HOME. Наличие ADB является страховкой, не лицензией на системные изменения.
