# P-02 — автоматическая проверка сборки Android

**Статус:** собираем и проверяем APK в CI, не выпускаем готовый к установке релиз. Целевая система: Android 9 (MiProjM05), но на настоящем проекторе сборка не испытывалась.

## Что делает workflow

Файл: `.github/workflows/android-build.yml`. На GitHub-hosted Linux он использует **JDK 17, Android SDK Platform 34 и Build Tools 34.0.0** и запускает существующий `build.sh` в новом безопасном CI-режиме.

Проверяются наличие и ZIP-структура файла, выравнивание (`zipalign`), Android minSdk 28 / targetSdk 33 и пакет `io.freemytv` (этот пакет будет изменён в P-03). Отчёт содержит SHA-256 APK и SHA коммита.

**Важно:** файл `FreeMyProjector-UNSIGNED.apk` — НЕ установочный APK. Android не сможет установить его, потому что он намеренно не подписан. Не отправляй этот файл на проектор. Именно этим мы не допускаем распространения сборки с известным паролем исходного Free My TV.

## Как посмотреть автоматическую проверку

1. Открой [GitHub Actions проекта](https://github.com/panasenkof/FreeMyProjector/actions).
2. Выбери **Android APK build (unsigned CI check)**.
3. Открой последний запуск для нужного коммита/PR.
4. Должна быть зелёная стадия `Android 9+ unsigned build smoke test`. Если красная — открой упавший шаг и пришли ссылку на запуск, без секретов.
5. В конце успешного запуска можно скачать артефакт **FreeMyProjector-UNSIGNED-NOT-INSTALLABLE**, хранящийся 14 дней.
6. Внутри — неподписанный APK, `SHA256SUMS.txt` и `BUILD-REPORT.txt`; последний указывает, что испытаний на проекторе не было.

Если файл отсутствует, workflow упал или артефакт уже истёк по retention — это не успешный выпуск APK.

## Как запустить вручную

После слияния workflow в `main`:

1. GitHub → Actions → **Android APK build (unsigned CI check)**.
2. Нажми **Run workflow**, выбери `main` и запусти.
3. После окончания просмотри логи и проверки. Повторный запуск не генерирует release key и не изменяет проектор.

## Что потребуется для пригодных к установке APK

Следующая спецификация **P-03** должна решить:
- отдельный package ID и название FreeMyProjector;
- постоянный секретный ключ подписи для обновлений, защищённое хранение и резервное копирование;
- безотзывную замену известных паролей, включая исходный `freemytv.keystore`;
- правила, по которым CI может выпускать **установочный** APK, а не только проверять компиляцию;
- безопасный механизм обновления и проверки `apksigner verify`, подписи и совместимости.

Не пытайся превращать CI-файл в устанавливаемый APK сторонними онлайн-подписывателями: это риск ключей и последующих обновлений.

## Как убедиться, что устройство не изменилось

Этот workflow вообще не подключается к проектору. Никаких `adb connect`, `adb install`, `cmd package set-home-activity` и настроек Wi-Fi он не выполняет. На этапе P-02 достаточно CI-тестов; аппаратная приёмка будет отдельно в P-05.

## Первоначальные ограничения унаследованного build.sh

Если запустить `./build.sh` **без** флага `FMP_BUILD_UNSIGNED=1`, он пока повторяет исходную логику с предсказуемым ключом/паролем. Это поведение меняется в P-03. До завершения P-03 не распространяй такие сборки и не устанавливай их как долгоживущие обновляемые версии.
