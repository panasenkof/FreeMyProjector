# P-05 — первый безопасный APK v0.1.1 (только обычное приложение)

**Статус 25.10.2026:** выпуск и установка на MiProjM05 пока не проводились. Эта версия содержит меню P-06, но **не** функцию домашнего экрана.

## Гарантии TEST / PREVIEW ONLY

- Package `com.fader.freemyprojector`, версия `0.1.1` / versionCode 1001; для подписи нужен **тот же ключ**, что и у выпуска `v0.1.0`.
- AndroidManifest: `SettingsActivity` включена как обычная Android TV программа, `HomeActivity android:enabled="false"` (нет возможности стать HOME из этой сборки), `HomeReceiver android:enabled="false"` (никакого автозапуска), `RemoteKeyService android:enabled="false"` (никакого перехвата клавиш).
- Дублирующая программная блокировка `ModeJob.PROJECTOR_HOME_SWITCH_AUDITED=false` сохраняется. В этой сборке вкладка «Кнопки пульта» не может реально включить Accessibility service.
- Прямые OEM экраны **фокусировки и трапеции в первой P-05 версии заблокированы** отдельным `P05_DIRECT_OPTICS_AUDITED=false`: нажатие на соответствующий пункт открывает корень заводских настроек, но не `FocusActivity`/`KeystoneActivity`. Причина — OEM Activity теоретически может запускать мотор/калибровку уже при открытии. Снять блокировку можно лишь после отдельного исследования и согласия.
- CI проверяет исходный и **скомпилированный** AndroidManifest; установка/удаление проекторного APK в CI не производится.
- **Не** перепривязывать пульт, не нажимать автокалибровку, не менять HOME, не запускать factory reset/OTA.

## Как выпустить APK

После слияния PR: [Actions → Publish signed FreeMyProjector APK (manual)](https://github.com/panasenkof/FreeMyProjector/actions/workflows/signed-release.yml) → **Run workflow** → `main`. Workflow требует существующие секреты подписи, не выводит пароль/keystore, проверяет пакет/подпись и публикует prerelease `v0.1.1`. Файлы: `FreeMyProjector-v0.1.1.apk`, `SHA256SUMS.txt`, `BUILD-REPORT.txt`. [GitHub Releases](https://github.com/panasenkof/FreeMyProjector/releases).

**Не скачивать** неподписанный `FreeMyProjector-UNSIGNED-NOT-INSTALLABLE` или старый `v0.1.0`: в нём ещё нет этого manifest gate.

Ни CI, ни этот PR не устанавливают APK на проектор. Установку как обычного APK пользователь разрешает и делает **отдельно**; она изменит список установленных приложений, но не прошивку. Рекомендован штатный интерфейс Android TV без присвоения приложению роли HOME. `adb install` тоже запись на устройство — никакие сценарии не вызывают её автоматически.

## Чек-лист ручного испытания (после отдельного решения об установке)

Отмечать `+ / - / ?`; для пунктов с неверным переходом дописать имя реально открытой заводской страницы.

| ID | Что сделать | Критерий |
| --- | --- | --- |
| S-01 | HOME до и после установки | Заводской Google TV HOME остался текущим, экран выбора HOME не появился |
| S-02 | Из списка приложений открыть FreeMyProjector | Открывается экран настроек без запроса назначить HOME |
| S-03 | Восемь строк главных настроек | Все видимы, стрелки/OK/Back, фокус не прыгает |
| S-04 | «Функции проектора» → шесть категорий | Оптика, изображение, HDMI, звук, подключения, система, Back корректно возвращает |
| S-05 | Фокус и трапеция | Заводские экраны или общий OEM fallback, выйти через Back, **ничего не регулировать** |
| S-06 | Пульт и Bluetooth | Открывается заводской экран добавления аксессуара или общий settings fallback, **не выполнять сопряжение** |
| S-07 | Изображение, HDMI, звук, Wi-Fi, системная информация | Отметить фактическое имя открытой страницы без изменения параметров |
| S-08 | HOME/Back комплектного пульта | Возвращают в Google TV HOME; штатные настройки работают |
| S-09 | Пункт 3D | Его **нет** |
| S-10 | Удаление FreeMyProjector | Обычное удаление приложения через системные настройки не затрагивает OEM |

Опционально отдельно проверить штатный сон/пробуждение, **без** жёсткого reboot и сброса пульта. Не включать доступ Accessibility: `RemoteKeyService` выключен. Сигналы о неполном доступе к OEM Activity — основание сделать следующую проверку и правку P-06, **не** повод менять системный пакет.

Если лаунчер/пульт перестали отвечать: остановить тест, не выполнять сторонние ADB write, перепрошивку, сбросы и отключения системных компонентов. Старый Android TV HOME остаётся по-прежнему штатным, но полного физического аварийного восстановления при потере ADB не доказано.
