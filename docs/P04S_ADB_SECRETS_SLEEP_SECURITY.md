# P-04S / P-07 — сетевая ADB, секреты и сон после пользовательского ревью

**Статус 25.10.2026:** проектор не изменялся; меры безопасности и аппаратный чек-лист. Все ADB/system/HOME операции остаются заблокированы до отдельного разрешения.

## 1. Репозиторий и подпись

По GitHub API `panasenkof/FreeMyProjector` на момент проверки **публичный**. Поэтому история файлов, авторство коммитов и адрес e-mail, если он записан в metadata Git, могут быть видны любому. Присланное ревью сообщает об отсутствии секретов в исследованных коммитах/PR, но **это не гарантирует отсутствие уже опубликованных или будущих секретов**.

Действия владельца вне Git (не присылать данные в чат):
1. Проверить, что пароль от `FreeMyProjector-release.p12` не хранится в `Текстовый документ.txt` рядом с ключом или в папке синхронизации. Если этот файл реально существует, перенести значение в проверенный менеджер паролей, сначала проверить, что запись доступна и защищена, затем безопасно убрать plaintext-файл и резервные копии с незашифрованным паролем.
2. Сохранить защищённую резервную копию **самого** `.p12` отдельно от пароля и проекта. **Не пересоздавать** signing key для `v0.1.1` — Android не примет обычное обновление APK с несовместимой подписью.
3. Открыть настройки GitHub Security/Advanced Security в этом репозитории и включить Secret scanning, push protection, Dependabot/security alerts, если эти функции доступны для текущего репозитория/тарифа. Применить branch protection на `main` по возможности.
4. Не коммитить baseline/firmware/keystore, пароли, `config.properties`, серийные номера, IP/MAC и токены. Отчёты об обнаружении утечек передавать без самих секретов, уже раскрытые токены ротировать.

## 2. TCP ADB port 5555

В исходном Free My TV клиент `Adb.java` обращается к `127.0.0.1:5555` **из приложения**, но это не доказывает, что системный `adbd` слушает только loopback. При включённой TCP debugging отладка может быть доступна другим устройствам локальной сети (в зависимости от bind/firewall/прошивки/авторизации). Нельзя утверждать ни «открыт всей сети», ни «точно закрыт» без проверки реального socket bind. Доверие к ADB не является аварийным гарантом при потере Wi-Fi/авторизации/загрузки.

**Будущий отдельный read-only аудит** (без передачи raw serial/IP): модель/build и user0, `getprop service.adb.tcp.port`, `getprop persist.adb.tcp.port`, список listening TCP sockets или ограниченная проверка host firewall. Никакого `adb tcpip`, `adb root`, `setprop`, `stop/start adbd`.

**Не отключать сетевую отладку немедленно на текущем аппарате ради теста**, пока не решён вопрос восстановления независимого доступа: через ADB у владельца сейчас есть основной технический канал, но не доказанный rescue при аварии. После safe P-05 trial и G1/G4 отдельно принять решение об отключении TCP debugging через заводское меню и перепроверить доступ/пульт; это системное изменение требует отдельного согласия.

## 3. Сон, заставка и выключение

В старом `HomeMode` изменялся `settings put secure screensaver_components`. В P-04R исполняемая ветка удалена: preview APK **не меняет** заводскую заставку, таймер сна, яркость лампы, энергосбережение, вентилятор или thermal protection.

При будущей авторизованной работе Home/Screensaver отдельно проверить:
- В штатном HOME записать наблюдение обычного ожидания/сна: выключается ли проекционная лампа по настройкам производителя, пробуждается ли штатным пультом.
- В обычном preview APK проверить только, что не изменены штатные настройки/поведение сна.
- В будущем HOME-пилоте проверять интервалы простоя, кадровую анимацию, влияние держания экрана активным и переход в настоящий standby; сравнить с базой до изменений. Никаких принудительных длительных перегревочных испытаний.
- Не добавлять прямой `KEYCODE_POWER` через ADB, sleep/wakelock hacks, автоматическое выключение лампы или собственный контроль оборотов вентилятора.

## 4. Невыполненные условия

Ни PR P-04R, ни P-06H, ни P-06Q **не** подтверждают на устройстве восстановление HOME после аварии, работу HDMI из FreeMyProjector как домашнего экрана, реальную экспортируемость OEM Focus/Keystone и сохранение BT/сна после смены HOME.

**Новый подписанный `v0.1.1` ещё не опубликован**. Сначала проверяем зелёные main CI и документацию, затем ручной workflow подписи, обычную установку владельцем без HOME (отдельное решение). Программа не должна предлагать неподтверждённый factory HOME chooser как мгновенный откат.
