# P-01: безопасная диагностика Xiaomi Mi Smart Projector

**Текущий этап:** по фотографии раздела «Об устройстве» от 22.10.2026 подтверждены системная модель `MiProjM05`, Android `9` и сборка `PQ3B.190705.003.4185`. **ADB и переключение системного лаунчера на этой прошивке ещё не проверялись**. Скрипт остаётся необязательным.

## Вариант А: самый простой, только с пультом (начни с него)

1. Включи проектор. Открой **Настройки** (значок шестерёнки).
2. Найди **Настройки устройства / Device Preferences → Об устройстве / About**. На некоторых прошивках пункты называются «О проекторе», «Система» или «Информация».
3. Перепиши **Модель**, **Версия Android TV / Android**, **Номер сборки**. Если какой-то строки нет — напиши «нет такого пункта»; ничего менять не нужно.
4. Отправь эти три строки в чат, не пересылая серийный номер, MAC-адрес, IP-адрес, имя Wi-Fi и данные аккаунтов.
5. На данном устройстве уже прочитана модель **MiProjM05**. **MJJGTYDS02FM** — предполагаемый розничный артикул из карточки продавца, а не значение системного меню. Не подгоняй ответ под него.

Это безопаснее ADB и **не требует ни компьютера, ни включения режима разработчика**.

## Вариант Б: read-only ADB-скрипт на Windows

Необязательно. Он помогает уточнить код устройства, Android SDK/API и доступный HOME-компонент, **но не переключает его**.

### 1. Подготовь инструменты

- Скачай исходники из **своего** [репозитория FreeMyProjector](https://github.com/panasenkof/FreeMyProjector) (после слияния PR) через **Code → Download ZIP**. Распакуй в удобный каталог Windows. Скачивай только из собственного репозитория.
- Если ADB ещё нет, скачай официальные **SDK Platform-Tools for Windows**: https://developer.android.com/tools/releases/platform-tools. Распакуй `platform-tools`. Полную Android Studio устанавливать не требуется.
- Открой PowerShell внутри распакованной папки проекта. Убедись, что это PowerShell 5.1 или новее: `$PSVersionTable.PSVersion`.
- В нашем скрипте по умолчанию вызывается команда `adb` из PATH. Если ADB не добавлен в PATH, передай полный путь к `adb.exe` через `-AdbPath` (см. примеры ниже).

### 2. Подключи проектор **только если хочешь использовать ADB**

Для диагностики по меню ADB не нужен. Для скрипта может потребоваться вручную включить режим разработчика и USB-отладку в **Настройках проектора**. Названия пунктов зависят от прошивки; обычно в «Об устройстве» несколько раз нажимают на пункт «Сборка», затем в появившихся настройках разработчика отдельно включают «USB debugging / Отладка по USB».

**Это опциональное изменение настройки безопасности**: включай отладку только если понимаешь её назначение. После диагностики рекомендуется её выключить.

- Подключайся по USB **только если на проекторе есть поддерживаемое USB-ADB подключение**.
- Подключение через Wi-Fi возможно **лишь если прошивка уже поддерживает отладку по сети**, а устройства находятся в доверенной локальной сети. Не открывай ADB-порт в интернет. Не исполняй `adb tcpip 5555` или команды изменения сети без отдельного анализа конкретной прошивки.
- Пункт `adb connect` вводится **вручную вне скрипта**, только если прошивка уже разрешает сетевую отладку. Например, в своём локальном PowerShell: `& "C:\platform-tools\adb.exe" connect "192.168.1.50:5555"`. Здесь `192.168.1.50` — условный пример адреса, подставь свой локальный IP и путь, **не присылай IP в чат**. Если ADB не подключается — пропусти этот вариант и используй вариант А.
- Когда проектор спросит **Разрешить отладку?**, реши самостоятельно. Не разрешай незнакомым компьютерам доступ.

### 3. Запусти только чтение

Из папки FreeMyProjector (в примере ADB лежит в `C:\platform-tools`):

```powershell
.\tools\read-only-device-info.ps1 -AdbPath "C:\platform-tools\adb.exe"
```

Если `adb` уже добавлен в PATH:

```powershell
.\tools\read-only-device-info.ps1
```

Для **локального** сохранения отчёта:

```powershell
.\tools\read-only-device-info.ps1 -AdbPath "C:\platform-tools\adb.exe" -OutputPath ".\device-info.local.json"
```

Без `-OutputPath` **ничего не сохраняется на диск**. С `-OutputPath` создаётся только указанный локальный JSON; файл специально исключён из Git через `.gitignore`. Скрипт **не отправляет данные в интернет**, не просит root и не изменяет HOME, Wi-Fi, службы или приложения проектора. Если при запуске PowerShell запрещает выполнение скриптов — сообщи текст ошибки; не ослабляй политику исполнения всей системы вслепую.

### 4. Как прочитать результат

В выводе будет JSON, например **условный**:

```json
{
  "schema_version": 1,
  "status": "connected",
  "source": "on-device",
  "fields": {
    "model": "Mi Smart Compact Projector",
    "device": "mantis",
    "android": "9",
    "sdk": "28",
    "build": "PQ3A.190801.002",
    "home_component": "com.google.android.tvlauncher/.MainActivity"
  },
  "note": "No settings or packages were changed. Check report before sharing."
}
```

**Это пример с вымышленными/тестовыми значениями, а не результат на твоём устройстве.**

- `connected`: ADB подключён, удалось запросить данные.
- `adb-not-found`: скрипт не нашёл ADB; укажи `-AdbPath`.
- `no-device`: устройство не подключено; переходи к варианту А либо проверяй подключение вручную.
- `unauthorized`: проектор не авторизовал этот компьютер; проверь запрос на самом проекторе.
- `offline`: подключение неактивно; ничего автоматически не переподключается.
- `multiple-devices`: больше одного устройства; скрипт ничего дальше не читает, чтобы не перепутать проекторы.
- `adb-error`: команда `adb devices` не выполнена; сырые логи и серийные номера не выводятся.
- `null` у отдельного поля: свойство отсутствует, не проходит форматную проверку или команда не поддерживается. Это **не доказательство отсутствия функции**.

Перед отправкой отчёта **открой его и проверь, нет ли чувствительной информации** — код сборки/модели может быть нетипичным. Отправляй только согласованные сведения. Не отправляй результат `adb devices`, `getprop` целиком или снимок настроек с серийным номером.

### 5. Что после проверки

Сообщи модель, версию Android, `sdk`, `build` и `home_component` (если получился). Затем мы сравним реальные данные с [планом](../PLAN.md), уточним спецификацию безопасного восстановления штатного экрана (P-04) и только после этого будем рассматривать переключение HOME.

**Ручная проверка на реальном проекторе ещё НЕ проводилась.** Автотесты в CI запускают подставной ADB и проверяют сценарии ошибок, безопасные команды и отсутствие серийных номеров в отчёте.
