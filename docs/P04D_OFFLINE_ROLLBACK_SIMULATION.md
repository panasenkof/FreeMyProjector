# P-04D — офлайн-симуляция восстановления для MiProjM05/Android 9

**Стадия:** mock-модель rollback, без доступа к устройству. Это **НЕ работающий инструмент восстановления**. HOME-switch остаётся заблокированным: `ModeJob.PROJECTOR_HOME_SWITCH_AUDITED=false`.

## Почему нужен журнал изменений

Read-only снимок от 25.10.2026 фиксирует точное исходное состояние HOME и всех 114 пакетов. Но одного снимка недостаточно, чтобы отличить наши действия от обновлений сторонних приложений. Поэтому настоящему восстановлению в будущем требуется **доверенный журнал только тех изменений, которые сделал FreeMyProjector с явного разрешения владельца**. Новые установленные приложения нельзя удалять из-за отсутствия в старом baseline, отключённые до эксперимента приложения нельзя автоматически включать.

## Реализация без реального устройства

`tools/Invoke-ProjectorRollbackSimulation.ps1` принимает **исходный локальный** каталог `MiProjM05-baseline-...`, `SHA256SUMS.txt` и **фиктивную модель устройства** в `-ScenarioPath` с маркером `OFFLINE_MOCK_ONLY`. Он не принимает путь к ADB и не вызывает сторонние программы. Сначала:
1. Проверяет checksum исходного JSON и идентичность модели, сборки и заводского HOME.
2. Проверяет фиктивные HOME-claimants, все состояния пакетов, журналируемые до/после, сохранение заводских OEM-пакетов. Неизвестный HOME/FallbackHome, ошибка прошивки или несогласованные изменения — STOP.
3. Составляет **только декларативный** план (возврат заводского HOME, затем возвращение лишь тех состояний пакетов, которые отражены в журнале).
4. Применяет шаги к копии данных **в оперативной памяти**, сравнивает результат с исходным baseline; `-FailAtStep` моделирует аварию на выбранном шаге.
5. Отчёт содержит `physical_device_access=none`, `device_writes=0`, `home_switch_blocked=true`. Запускает 0 реальных команд управления.

**Не кормить инструмент реальными журналами!** Пока нет разрешённого функционала записи таких журналов, тесты генерируют искусственные сценарии в временной папке CI. В репозитории нет приватного JSON владельца.

## Проверки

`tests/Test-ProjectorRollbackSimulation.ps1` для Windows PowerShell 5.1: начальное состояние/no-op, гипотетический другой HOME и пакет, исходно **отключённый** пакет, возврат только HOME, возврат только пакетов, принудительный сбой перед шагами 1/2, невозможность обратиться к настоящему ADB, повреждение SHA, другая прошивка, FallbackHome, пропавший пакет, изменённая/отключённая OEM-служба, изменения без журнала и попытка добавить в журнал системный пакет.

## Упрощённый тест на Windows с личным снимком (25.10.2026)

Снимок владельца уже проверен (`sha256=match`, 114 пакетов, исходный HOME). Теперь можно выполнить **офлайн dry-run именно по этому локальному снимку** без ADB, проектора, установки APK и изменения системы:

```powershell
cd D:\Git\FreeMyProjector\FreeMyProjector-main
git pull --ff-only origin main
$folder = 'D:\Git\FreeMyProjector\MiProjM05-baseline-20261025-091132-80cc72ea6d'
.\tools\Test-ProjectorRollbackLocally.ps1 -SnapshotDirectory $folder
```

Скрипт вначале проверяет SHA-256 исходного снимка, затем в **временных фиктивных JSON-моделях**, созданных **рядом с Git-копией** в `D:\Git\FreeMyProjector`, симулирует: уже исходное состояние (0 шагов), возврат заводского HOME (1 шаг), аварию перед восстановлением HOME; если в списке нашёлся один из специально разрешённых тестовых пакетов — также мнимую смену состояния этого пакета вместе с HOME и отказ перед вторым шагом. Действительно установленное приложение **никогда** не изменяется — все изменения только в словаре модели. Временные модели автоматически удаляются даже при ошибке (кроме аварийного завершения процесса/ПК; при таком сбое оставшиеся каталоги `fmp-p04d-local-mock-*` можно удалить вручную, предварительно убедившись в их имени). Не публиковать исходный JSON.

Успешный результат: `status=passed`, `mode=OFFLINE_MOCK_ONLY`, `original_snapshot_unchanged=true`, `device_access=none`, `device_writes=0`, `home_switch_blocked=true`. В отдельных случаях `mock-failure-injected` **ожидаемое прохождение теста**, демонстрирует обнаружение аварии, а не ошибку запуска.

**Это не тест настоящего Android 9 HOME chooser или способности ADB восстановить оболочку**, не полный бэкап прошивки и не безопасное подтверждение HOME-пилота. Сохранённый снимок остаётся неизменным, вызывать команды переключения HOME нельзя.

Для отдельного регрессионного набора, не использующего частный baseline владельца:

```powershell
.\tests\Test-ProjectorRollbackSimulation.ps1
```

## Что необходимо ДО реального rollback

- Отдельный детально проверенный **write-стек** для Android 9 без `cmd role` как универсального fallback, с проверкой фактически выбранного HOME после каждой операции и документированием всех ошибок.
- Атомарное сохранение/подтверждение журнала на компьютере **до изменения**. При отсутствии журнала — STOP, никакого восстановления «наугад».
- Независимый способ управления при потере HOME, ADB и пульта; проверка аварийного входа.
- Отдельное разрешение на изменение системы и аппаратная проверка.
- Не отключать Google TV Launcher, Fengmi, Formovie, Droidlogic, Camera2 и другие защищённые компоненты; никаких массовых `pm enable`.
