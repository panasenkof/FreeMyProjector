# FreeMyProjector — единый план работ

**Актуально на 22.10.2026.** Этот файл — единственный оперативный план и источник статусов. Технические подробности о железе и проверках см. в [docs/PROJECTOR_COMPATIBILITY.md](docs/PROJECTOR_COMPATIBILITY.md), правила SDD — в [docs/SDD_GUIDE.md](docs/SDD_GUIDE.md). Каждое изменение реализуется через согласуемую спецификацию в папке [openspec/changes](openspec/changes).

**Цель:** независимая, управляемая с пульта, безопасно отключаемая оболочка на основе Free My TV для Xiaomi Mi Smart Compact Projector (реальная системная модель `MiProjM05`, Android 9; товарный артикул `MJJGTYDS02FM` ещё не подтверждён наклейкой), плюс отдельное исследование и улучшение работы YouTube в РФ. *Работоспособность на данном проекторе пока не доказана.*

## 3. Обязательный SDD-процесс для каждого пункта

1. **Исследование** текущего поведения и ограничений (из кода и реального устройства, без домыслов).
2. **Proposal**: проблема, цель, эффект, область изменений и не-цели.
3. **Spec**: требования на наблюдаемое поведение и сценарии «когда → тогда», отрицательные сценарии и критерии приёмки.
4. **Design**: архитектура, затрагиваемые файлы, совместимость с Android 9, безопасность/откат.
5. **Tasks**: маленькие проверяемые шаги, автотесты, ручные проверки; привязка требований к тестам.
6. **Согласование**: пользователь подтверждает важные требования и действия, влияющие на устройство; до этого не внедрять рискованные изменения.
7. **Реализация через PR**: код, тесты и документация, линк на spec, результат CI; затем чек-лист реального теста.
8. **Сверка и закрытие**: найти пробелы между требованиями и реализацией; после ручного подтверждения актуализировать `openspec/specs/`, архивировать change и обновить PLAN.

Для небольших исправлений можно объединить proposal и design в короткие документы, но **не пропускать проверяемые требования и критерии готовности**. Нельзя выдавать непроверенное на устройстве за проверенное.

## 4. Принципы / ограничения

- Первые релизы: Android TV 9 / API 28+, сборка Java без Gradle на базе существующего `build.sh`. Переход на Gradle — только при обоснованной необходимости.
- Без root по умолчанию. Нельзя отключать/удалять системные пакеты, менять настройки сетей или HOME без явного разрешения, плана восстановления и проверки команд на точной прошивке.
- Не переносить бездумно инструкции оригинального `CLAUDE.md` для TCL/Google TV на Xiaomi; актуальные ограничения проекта — [AGENTS.md](AGENTS.md).
- Разделять **безопасное исследование** (выполняется до изменения системы) и **реализацию** (только после принятой спецификации).
- Перед отправкой в PR проверять отсутствие API-токенов, keystore, паролей и приватных сетевых параметров.
- Улучшение YouTube не следует из замены лаунчера; сетевую эффективность надо измерять до выбора способа.
- Изменения, сломавшие штатный HOME/управление пультом, считаются P0-регрессией, даже если остальные функции работают.
- Скрипты автоматизации не должны заявлять успешный тест на проекторе без реального результата.

## 6. Риски и условия пересмотра приоритета

| Риск | Реакция |
|---|---|
| Прошивка Xiaomi блокирует ADB или HOME-switch | Остановить изменение системы, исследовать доступные механизмы лаунчера и альтернативный запуск приложения |
| Не восстанавливается родной домашний экран | Не проводить опыт; сначала безопасный rollback (P-04) |
| Совпадает package ID с оригиналом либо подпись непостоянна | Решить P-03 до публикации APK |
| Реальная модель отличается от предполагаемой | Обновить P-01, требования Android и совместимость, не строить предположения по карточке продавца |
| Сетевые способы не поддерживаются Android 9 или ломают остальные приложения | Исключить неподходящие решения, оставить отключаемые варианты |
| Избыточная документация затормаживает разработку | Уменьшать размер артефактов, но оставлять тестируемые требования, критерии и состояние проверок |
