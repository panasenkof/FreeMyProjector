# P-02: Автоматическая сборка и проверка Android APK

**План:** [PLAN.md](../../../PLAN.md), пункт P-02  
**Состояние:** спецификация сформирована перед реализацией, рабочий PR; сборка на реальном проекторе не проверялась.

## Зачем

FreeMyProjector наследует Java-приложение Free My TV, которое собирается `build.sh` без Gradle. Сейчас в репозитории нет CI, автоматически проверяющего сборку Android, а локальный скрипт создаёт APK с заведомо известным паролем keystore. Публикация такого APK как готового обновляемого приложения была бы небезопасна.

## Что изменится

- В GitHub Actions появляется воспроизводимая проверка сборки Android с JDK 17 и Android SDK API 34 / Build Tools 34.0.0.
- `build.sh` получает **опциональный** режим компиляции без создания ключа/подписи. Обычная локальная логика не изменяется в рамках P-02; её безопасность будет рассмотрена в P-03.
- CI проверяет результат `aapt2`, `javac`, `d8`, `zipalign`, структуру APK и API compatibility metadata.
- При успешном запуске CI загружает **неподписанный** APK и отчёт проверки как артефакт исключительно для ревью разработчиком, **не** как готовый к установке релиз.
- Документация объясняет, как найти логи/артефакт в GitHub, чем отличается проверка сборки от испытаний на проекторе, и что потребуется для P-03.

## Что НЕ входит

- Нет готового к установке или обновлению APK в Releases.
- Нет генерации или хранения release keystore в CI. Ни один секрет подписи не запрашивается в рамках P-02.
- Нет смены Android package name, Launcher/HOME, настроек устройства или сетевых функций; это P-03—P-05.
- Нет автоматического установки APK на проектор, подключения ADB, root и публикации в магазины.
- Полноценные unit/UI-тесты Android и измерение FPS/памяти — отдельные задачи; этот change вводит build-smoke проверки.

## Риски и решения

1. **Известный пароль подписи в upstream:** CI не вызывает шаг подписания, не создаёт keystore, не публикует устанавливаемый APK.
2. **Разные версии инструментов:** CI фиксирует JDK 17, платформу 34 и Build Tools 34.0.0; не выбирает случайную последнюю установленную версию.
3. **Сборка ещё не равна совместимости с MiProjM05:** нельзя считать APK проверенным на Android 9 только на основании компиляции.
4. **Секреты/конфигурация:** CI использует пустой `tmdb_key` из `config.example.properties` и не раскрывает значения приватной локальной конфигурации.

## Проверка готовности

OpenSpec validation и CI Android build должны проходить на предлагаемом PR. Артефакт с названием `UNSIGNED-NOT-INSTALLABLE` содержит неподписанный APK, manifest metadata и SHA-256. Статус P-02 после CI: «проверка сборки выполнена», а не «проверено на проекторе».
