## ADDED Requirements

### Requirement: Воспроизводимая Android-сборка без изменения основного приложения
Build workflow SHALL компилировать существующий Java-проект `build.sh` на GitHub-hosted Linux с явными JDK 17, Android SDK platform 34 и build-tools 34.0.0, сохраняя текущие `minSdkVersion=28` и `targetSdkVersion=33`.

#### Scenario: Коммит или Pull Request с изменениями Android
- **WHEN** CI запускается при изменении исходников Android, `build.sh`, конфигурации сборки или workflow
- **THEN** GitHub Actions выполняет компиляцию и проверку APK с закреплёнными версиями инструментов

#### Scenario: Отсутствует необходимый инструмент или ошибка компиляции
- **WHEN** один из этапов сборки завершился ошибкой или результат отсутствует
- **THEN** workflow получает статус failure и не выдаёт неполный APK за успешный артефакт

### Requirement: Неподписанная сборка для CI
CI SHALL иметь отдельный явно включаемый режим, в котором создаётся выровненный **неподписанный** APK, не генерируется keystore и не применяется исходная парольная подпись Free My TV.

#### Scenario: CI-сборка без ключа
- **WHEN** вызывается `build.sh` с `FMP_BUILD_UNSIGNED=1`
- **THEN** создаётся `out/aligned.apk` и не выполняются `keytool` или `apksigner sign`

#### Scenario: Обычный локальный запуск
- **WHEN** флаг `FMP_BUILD_UNSIGNED` не задан
- **THEN** исторический режим `build.sh` продолжает вести себя по-прежнему; его переустройство и безопасная подпись отложены до P-03

### Requirement: Проверка APK после сборки
Workflow SHALL проверить, что неподписанный APK существует, не пустой, является читаемым ZIP/APK, имеет корректное выравнивание и заявляет необходимые Android min/target SDK; SHALL создать SHA-256 отчёт.

#### Scenario: Валидный APK
- **WHEN** сборка завершена
- **THEN** проверки `unzip -t`, `zipalign -c`, `aapt2 dump badging` и минимум 28 / цель 33 проходят, а SHA-256 сохраняется с точным именем файла

#### Scenario: Некорректная сборка или неверные SDK
- **WHEN** повреждён APK или manifest содержит неожиданную Android API политику
- **THEN** workflow падает и не публикует успешный build artifact

### Requirement: Недопустимость распространения тестовой сборки как релиза
CI SHALL явно отмечать артефакт как `UNSIGNED-NOT-INSTALLABLE`, ограничивать срок хранения и не создавать GitHub Release или постоянно подписанный APK.

#### Scenario: Успешная сборка PR
- **WHEN** CI проходит на PR
- **THEN** в Actions появляется скачиваемый артефакт только для анализа, включающий unsigned APK и проверочный отчёт с указанием коммита

#### Scenario: Ошибка компиляции
- **WHEN** CI завершился с ошибкой
- **THEN** в Actions остаются логи ошибки; скачать якобы готовый к установке APK невозможно

### Requirement: Безопасная граница ответственности
CI SHALL не использовать секреты подписи, не сохранять локальный `config.properties`, не обращаться к проектору и не выполнять ADB-команды.

#### Scenario: Запуск на Pull Request
- **WHEN** CI обрабатывает непроверенный PR
- **THEN** он имеет доступ только на чтение репозитория, не получает signing secrets и не выполняет установку или команды управления реальным устройством
