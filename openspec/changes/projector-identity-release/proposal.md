# Proposal P-03 — собственная идентичность и безопасная подпись FreeMyProjector

**Roadmap:** [PLAN.md](../../../PLAN.md), P-03. **Предшествует установке на MiProjM05.**

## Проблема
Унаследованный APK использует пакет `io.freemytv`, видимое имя Free My TV и подпись с общеизвестным паролем (`freemytv`). Это создаёт риск коллизий и небезопасных обновлений. Сейчас CI создаёт только unsigned APK (P-02).

## Результат
- Android package ID `com.panasenkof.freemyprojector`, видимое имя `FreeMyProjector`. Java-классы можно сохранить в пространстве имён `io.freemytv`, но **все manifest-классы должны быть полными именами**, а ADB-компоненты использовать новый package ID.
- Сборка `build.sh` по умолчанию не подписывает APK, не генерирует keystore и не пользуется фиксированными паролями. Подписание допускается исключительно с явно переданными приватным keystore и секретными параметрами; проверяется подпись.
- На PR автоматически проверяется новая идентичность APK, правильность Java/manifest-компонентов, отсутствие секретов и возможность unsigned-сборки.
- Отдельный `workflow_dispatch` GitHub Actions из `main` выполняет **только после настройки секретов пользователем** приватное подписание, проверку `apksigner verify` и публикацию prerelease GitHub Release с SHA256 и SHA коммита.
- Установочные версии имеют монотонно растущий `versionCode` и явный `versionName`; одинаковый пакет и сертификат для всех обновлений.
- Русская инструкция по созданию, офлайновому резервному копированию и подключению **собственного** ключа (секреты не присылать в чат).

## Не-цели
- Не устанавливаем APK, не меняем HOME, не меняем Wi-Fi или прошивку, не вызываем ADB на пользовательском устройстве. P-04/P-05 — отдельные задачи.
- Не переносим настройки/данные старого `io.freemytv` автоматически; новое приложение устанавливается параллельно как самостоятельное.
- Не публикуем Release без приватных секретов владельца и его ручного запуска. Нельзя утверждать, что установочный APK уже выпущен, пока не выполнены условия.
- Никакого изменения системной архитектуры Java или редизайна.

## Угрозы и ограничения
- Потеря keystore или пароля = невозможность обновить ранее установленный пакет обычным способом. Требуется резервное копирование до первого релиза.
- PR из fork или любой обычный build **не получает signing secrets** и write-доступ к Releases.
- Временные файлы ключа должны находиться вне workspace и удаляться даже при сбое.
- Команды запуска HOME из Free My TV пока не проверены на Xiaomi: идентичность компонентов проверяется статически, их работоспособность — P-04/P-05.
- Первый выпуск возможен **только после пользовательской настройки GitHub Secrets** и ручного запуска. Отсутствие секретов — ожидаемое безопасное состояние.
