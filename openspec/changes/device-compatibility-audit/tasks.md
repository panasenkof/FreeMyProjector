# Tasks: device compatibility audit (P-01)

**Статус:** пользователь согласовал два способа диагностики; реализация ожидает проверки CI и обязательной ручной сверки. Справочник: [PLAN.md](../../../PLAN.md).

## 1. Согласование требований

- [x] 1.1 Пользователь выбрал ручную инструкцию **и** необязательный read-only скрипт Windows.
- [x] 1.2 Принято консервативное обезличивание и ручная проверка перед отправкой: в репозиторий не попадают идентификаторы устройства; публикации автоматически нет.
- [x] 1.3 Согласованный scope отражён в proposal/spec/design/tasks; review CI ещё ожидается.

## 2. Реализация после согласования

- [x] 2.1 Добавлена [инструкция Windows/ручной путь](../../../docs/DEVICE_DIAGNOSTICS_WINDOWS.md) с вариантами пунктов меню и ошибками.
- [x] 2.2 Скрипт [tools/read-only-device-info.ps1](../../../tools/read-only-device-info.ps1) реализован с whitelist ADB-команд; ожидает CI.
- [x] 2.3 В коде предусмотрены неизвестные поля, unauthorized/offline, no-ADB, несколько устройств; ожидает CI.
- [x] 2.4 JSON без серийных идентификаторов, локальная запись только с `-OutputPath`, предупреждение о ручной проверке; ожидает CI.

## 3. Проверки и приемка

- [ ] 3.1 Автотест: типовой ответ модели/Android/сборки.
- [ ] 3.2 Автотест: no-ADB / offline / unauthorized / unsupported без изменения состояния.
- [ ] 3.3 Статическая проверка отсутствия запрещённых ADB-команд, root, секретов и сетевой отправки.
- [x] 3.4 Указано, что реальных устройств/прошивок пока не проверяли.
- [ ] 3.5 Ручная сверка результатов со страницей «Об устройстве» на реальном проекторе (требует владельца).
- [ ] 3.6 Только после ручного подтверждения обновить `PLAN.md`, перенести принятый контракт в `openspec/specs/device-compatibility/spec.md` и архивировать изменение.
