# Design: read-only Xiaomi diagnostics

**Статус:** проект решения, подлежит проверке в рамках P-01; никакой код сейчас не реализован.

## Выбранный подход

1. Сначала подготовить пользовательскую инструкцию (без обязательного ПК) для отображения модели, версии Android и номера сборки в меню «Об устройстве».
2. По отдельному согласию пользователя — необязательный `tools/read-only-device-info.ps1` для Windows PowerShell. Он проверяет наличие `adb` и подключение и выполняет белый список **только читающих** команд.
3. Скрипт собирает минимальный отчёт в локальном текстовом файле (по умолчанию без автоматической отправки) и явно помечает пропущенные поля.
4. Все поля помечаются как `source=on-device`, `source=manual`, `source=seller-estimate` или `unknown`; не пытаться подобрать модель по созвучному названию.
5. Перед любой реализацией изучить точный синтаксис и доступность диагностических команд на Android TV 9 и корректность работы на Windows PowerShell 5.1+.

## Разрешённые операции ADB (предварительный whitelist)

- `adb version`, `adb devices` (не сохранять список уникальных серийных идентификаторов в отчёт).
- `adb shell getprop ro.product.model`.
- `adb shell getprop ro.product.device`.
- `adb shell getprop ro.build.version.release`.
- `adb shell getprop ro.build.version.sdk`.
- `adb shell getprop ro.build.display.id`.
- Необязательное чтение обработчиков HOME после проверки синтаксиса Android: `cmd package resolve-activity`; ошибки разрешены и не должны запускать корректирующие команды.

**Запрещены:** `pm disable`, `pm uninstall`, `pm clear`, `cmd package set-home-activity`, `settings put`, `svc wifi`, `cmd wifi forget-network`, `adb install`, `adb shell su`, другие команды изменения состояния.

## Формат результата

- Локальные сведения о типе устройства: модель, код устройства, версия Android, SDK/API, отображаемая сборка.
- Для каждого поля: значение или «не определено» и источник.
- Список безопасных проблем доступа: ADB не найден, unauthorized, offline, permission denied, unsupported.
- Резюме о совпадении/несовпадении с ожидаемой моделью и пометка «HOME не проверялся и не переключался».
- Ни одной автоматически отправляемой сетевой заявки; при ручном распространении пользователь проверяет отчёт.

## Тесты

- Автоматические: подставной вывод ADB (успех, отсутствующий `adb`, unauthorized, offline, нестандартная строка, пустой ответ), доказательство что вызываются только операции whitelist.
- Статические: проверить, что нет запрещённых команд и вызова сетевых API.
- Ручные: сверка с экранами устройства; подтвердить отсутствие изменений интерфейса, сети и приложений; не считать тест пройденным до реального устройства.

## Альтернативы

- Только ручная проверка: минимальный риск, но труднее воспроизводить технические детали. Она обязательно остаётся доступной.
- Автоматизированная проверка через root или системные настройки: отклонена как неоправданно рискованная.
