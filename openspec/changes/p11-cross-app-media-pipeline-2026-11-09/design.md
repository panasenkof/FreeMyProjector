# Design — P-11

1. Запрашивать минимум данных: ручное состояние YouTube, других видео, системных звуков, audio output, сна, формата потока и времени.
2. После проверки P-04E два последовательных пассивных снимка через `adb shell dumpsys audio`, `media.audio_policy`, `media.audio_flinger`, необязательные `media.codec`, `media.resource_manager` и `adb logcat -d` с фильтром media tags; без `logcat -c`.
3. `good` и `bad` формировать только локально на ПК; исключить raw dumps/логи из Git (`.gitignore`). Не выводить serial/IP/SSID/частные URL в PR.
4. **Сначала сравнить Bluetooth A2DP route vs встроенные динамики**. При дефекте снять bad-данные ДО ручного отключения внешней аудиоколонки; затем отключить только колонку или выбрать встроенный звук (не выключать Bluetooth целиком из-за пульта), сравнить тот же файл, потом штатно переподключить её. При необходимости сравнить negotiated audio codec (SBC/AAC/LDAC) только по доступным штатным read-only полям. Сравнивать clocks, audio routes, session/thread states, decoder resource errors. Нехватка сервиса/поля на Android 9 обозначается «недоступно», а не «нет проблемы».
5. Ручные обходы (Force stop, stereo PCM vs passthrough) — только после фиксации параметров и отдельного разрешения пользователя, по одному изменению за раз с возвратом настройки. Не включать «перезапуск audioserver» в FreeMyProjector.
6. Внешние свидетельства от других моделей применять только как гипотезы, а не подтверждённую совместимость или готовое решение для `.4185`.
7. После определения причины отдельный инженерный PR только для изменений в **нашей** APK без системных прав; если виновата прошивка — рекомендация OEM update/обращение в Xiaomi.
